# Guidance for Problem Decomposition

## Reframing prompts

- "What is another valid way to describe this problem?"
- "Is this mainly a symptom, root cause, constraint, or decision?"
- "Who would define this problem differently and why?"
- "What happens if the current framing is wrong?"

## Examples of good factors (by domain)

### Technical/Software
- Failing API, team capacity, deadline pressure, legacy dependency,
  missing docs, unclear ownership, observability gaps

### Personal/Career
- Financial runway, manager relationship, skill gaps, market timing,
  energy levels, family obligations, support network

### Strategic/Business
- Customer segment impact, competitor moves, regulation deadline,
  team morale, cash flow, partnership dependencies

### Operations/Process
- Handoff friction, queue size, SLA pressure, ownership boundaries,
  tooling limits, approval bottlenecks

### Learning/Research
- Unknown concepts, source quality, experiment time, confidence level,
  feedback loop speed, access to mentors

## Probing questions when user is stuck

### Can't list factors:
- "Who else is affected by this besides you?"
- "What decisions were made before that led here?"
- "What would make this problem disappear overnight?"
- "What's the most annoying part of this situation?"

### Factors too vague:
- "Can you give a specific example of [vague factor]?"
- "What does [factor] look like in practice?"
- "If you had to explain [factor] to someone new, what would you say?"

### Can't find connections:
- "If [factor A] disappeared, would [factor B] still exist?"
- "Which factor showed up first chronologically?"
- "Which factor, if solved, would make the others easier?"

### Can't prioritize:
- "Which one keeps you up at night?"
- "Which one, if ignored, gets worse fastest?"
- "Which one is blocking progress on the others?"

## System-mapping prompts

- "Who are the key actors and what does each one optimize for?"
- "What resources flow through this system (time, money, information, trust)?"
- "Where does work slow down or get stuck?"
- "Which dependency creates cascading delays?"

## Leverage-point prompts

- "Which factor influences the most other factors?"
- "Which change is small but high impact?"
- "Which action is reversible if we are wrong?"
- "Which first action teaches us the most quickly?"

## Uncertainty-reduction prompts

- "What do you know from evidence vs assumption?"
- "What evidence would change your mind?"
- "What is the most important unknown blocking action?"
- "What quick test could reduce uncertainty this week?"

## Domain-specific framing for constraints

| Domain | Constraints might be... |
|--------|------------------------|
| Technical | Stack, time, team size, backwards compatibility, performance, security |
| Personal | Values, energy, money, relationships, location, health |
| Business | Budget, regulation, market window, brand, existing contracts, headcount |
| Operations | SLA targets, staffing, tooling, compliance, process rigidity |
| Learning | Time to study, source quality, available mentors, practice opportunities |

## Domain-specific framing for success criteria

| Domain | Success looks like... |
|--------|----------------------|
| Technical | Tests pass, no regressions, deploys cleanly, users don't notice, performance holds |
| Personal | Feels right in 6 months, relationships intact, energy improved, no regret |
| Business | Revenue target hit, churn reduced, team retained, customers satisfied |
| Operations | Throughput improves, fewer handoff delays, SLA stability, lower rework |
| Learning | Can explain clearly, apply in practice, fewer repeated mistakes, faster decisions |
